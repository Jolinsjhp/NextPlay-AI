## 检查结果

本次实际读取 40 场、150,466 个事件、91,031 个决策。没有发现逐场重复事件 ID、事件与球员名册关联错误、重复决策 ID，或决策持球者/时间/比分与快照不一致。566 名球员中 471 份背景 profile 为 complete、95 份 partial；惯用脚未知 3 人。这里的完整性不代表属性效果已经经过验证。

只有 4 场保存全场 tracking，36 场有决策快照而没有完整连续轨迹。这足以支持当前逐决策比较，不能把它介绍成全部比赛均能连续追踪。

## P1：带球过程中没有正常的失球/抢断分支

证据：`generate.py:537–545` 中带球直接把球附在持球者脚边；`generate.py:572–576` 中带球结束只记录 carry 并选择下一动作；`generate.py:667–678` 中近距离防守只生成 pressure 标签。对正常的开放比赛带球，没有球员碰撞/抢断导致球权转移的状态转移。行政事件可以中断动作，不能替代正常抢断模型。

影响：逼抢者贴近仍不能正常夺回球权，模拟的带球收益和控球链条可能偏乐观。不能用这些结果验证真实带球安全性。可信度：高，直接代码路径。

建议：A 优先增加接触、护球、抢断、失误与界外分支；固定种子验证不同压力下控球保持率，以及动作中断时事件/球权/坐标一致。参数未经真实数据验证时明确标为假设。

## P1：传球与射门是先抽结果，再把轨迹导向结果

证据：`generate.py:502–505` 先抽传球成功，失败就将接球者改为防守者；`generate.py:542–544` 每帧把球插值到这个接收者的实时脚边。`generate.py:521–534` 先抽 goal/saved/off_target，再设置对应终点。`realism/policy.py:32–39` 的线路拦截时间影响候选选择权重，但执行成功率主要仍由距离和二元 pressure 频率决定。

影响：动画连贯不等于物理模拟；防守站位与实际拦截结果之间的联系很弱。对于比较两条传球路线，这是关键局限。失败传球实际终点还是防守者位置，与意图传球长度也不是同一口径。可信度：高。

建议：先固定出球方向、目标和初速度，再按防守到达时间解析接触和球权；分别保存 intended_target 与 resolved_end。必须更换结果模型/重生成数据后重新校准 B，不能只修动画。

## P1：比分、时间和比赛目标没有进入生成策略

复现：同一球员站位和属性下，将比分改成 0–1、时间改到 5900 秒，`realism.policy.candidates()` 返回完全相同的动作集合与权重。`policy.py` 不读取比分或时间，`Model.action_weights()` 主要按球场区域取值。

影响：不能学习领先方控制风险、落后方追分、淘汰赛保平进入加时等策略差异。即便 C 用大模型解释了这些情境，也不代表 A/B 已按情境评分。可信度：高，代码加可重现对照。

建议：先明确赛制与目标（联赛积分、单场淘汰、两回合总比分等），再增加 score_margin、nominal_time_remaining、目标和风险偏好。保持“动作威胁价值”与“比赛目标价值”分开。C/D 现在只增加观测比分和名义剩余时间背景，规则未知保持未知，不改 Q2 分数。

## P1：动作份额接近，空间行为仍偏离参考

本次重算与仓库 system-validation 的模拟值一致：

| 指标 | 当前模拟 | 仓库保存的真实参考 |
|---|---:|---:|
| 全部选定地面传球回传比例 | 59.31%（41,760 次传球） | 38.62%（2,320 次传球） |
| 进攻方向最后四分之一区域的回传比例 | 88.53%（16,128 次传球） | 50.00%（254 次传球） |
| 平均传球距离 | 20.84 m | 15.01 m |
| 前场四分之一区域平均传球距离 | 23.13 m | 11.46 m |
| 前场四分之一区域传球成功率 | 93.30% | 79.13% |

真实参考是仓库保存的 8 场世界杯筛选事件统计，不是英超总体，也不是本次重新下载的独立盲测；失败传球终点定义和压力定义还存在差异。这些是偏差诊断，不是所有差距都应强行拟合到参考值。

可能原因：固定接应阵型使持球者前方缺少合适接球点、按区域频率归一化、压力和失败轨迹模型过简。前场动作份额拟合不能单独定位因果。应按区域、领先/落后、压力和进攻阶段分层，再做接应策略与执行模型的消融。

## P2：球员背景已导入，但并非个性化真实能力模型

证据：`realism/player_actions.py:14–39` 的雷达属性系数为人工指定且有边界的风格假设；只调 pass/carry/shot 的选择权重。`realism/model.py:23–29` 的执行模型依赖距离/pressure 或射门距离分桶。惯用脚有记录，不等于已按左右脚、身体朝向和防守遮挡计算成功率。

影响：可以称为“有球员背景的模拟”，不能称为“已验证某真实球员在此动作下的成功率”。建议分别列出 observed / derived / assumed / unknown，先实现可解释的惯用脚敏感性场景，并明确未校准。

## P2：原仓库 Agent 仍走旧版传球分析

证据：`decision/agents.py:51–56` 仅保留部分帧字段与 player_id/team_id，并调用旧 `engine.analyze()`；不保留比分和完整属性，也不是 B 的新版 pass/carry/shot Q2 比较。原 `coach.html` 与后来加入的 B 分析入口存在产品/算法分叉。

影响：新增了数据，不会自动让旧 Agent 看到全部背景；不同页面可能用不同评分。当前 C/D 分支已另接 canonical `/api/decision-analysis/agents`，并把侧栏入口指向整合分析页，但这还没有推送到上述远程仓库。

## 建议分工顺序

1. A：先修带球失球与传球轨迹解析，再改善前场接应；在这些规则稳定后重生成数据。
2. A/B：加入比赛目标字段，决定哪些只做解释，哪些进入目标价值模型；重建版本和离线评估，不能沿用旧散列/旧基准宣称兼容。
3. B：在独立真实片段上验证排序与风险判断，明确模拟生成器与反事实模型的差异。分布接近和合成数据内回测不证明真实决策正确。
4. C/D：使用唯一候选集、清楚区分观测与假设，完成真实 Foundry 工具调用及三个案例单/多 Agent 对照；保留无模型可演示路径。
